# i18n — lazy dictionary loading & scoping

Related issue: **#225 perf(i18n): load locale dictionaries on demand and reduce client message payloads**

## Architecture

| Module | Role | JSON imported? |
|--------|------|----------------|
| `lib/i18n/messages.ts` | Pure helpers: `lookup`, `interpolate`, `translate`, `scopedMessages`, `MessageTree`, `Replacements` | **No** — safe to import anywhere |
| `lib/i18n/dictionaries.ts` | Loader: `getDictionary(locale)` (async), `enDict` (static English) | `en` statically, `es` via `await import()` |
| `lib/i18n/provider.tsx` | Client provider: `useI18n()`, `useI18nNamespace()` | via `./dictionaries` |
| `lib/i18n/server.ts` | Server helpers: `getServerLocale`, `getServerDictionary`, `tr`, `formatMoneyServer`, `dealStatusLabel` | via `./dictionaries` |

### Why English stays statically imported

The client provider needs a **synchronous** fallback dictionary: `t()` must resolve a
missing key to English (and finally to the raw key) during the very first render.
Keeping `enDict` static preserves that contract while still avoiding the eager
bundle of the second locale.

The Spanish dictionary is behind a statically analyzable dynamic import, so the
bundler emits it as a **separate chunk** that is only requested when the locale
is actually `es`:

```ts
const module = await import('@/messages/es.json')
```

## Locale switching

`I18nProvider.changeLocale` is atomic and race-safe:

1. The cookie (`mercato-locale`) and `<html lang>` are updated immediately.
2. The dictionary for the target locale is awaited.
3. Locale **and** messages are applied in the same commit, then `router.refresh()` runs.
4. A request-ID guard drops results from superseded toggles (rapid `es`/`en` switching).
5. If the dictionary fails to load, the locale is kept and messages fall back to
   English so the UI stays usable.

## Namespace scoping

Translations are grouped by route namespace (`landing.*`, `deals.*`, `dashboard.*`,
`events.*`, …). Components can consume a namespace directly:

```tsx
import { useI18nNamespace } from '@/lib/i18n/provider'

export function HeroComparisonCard() {
  // t('rates.options.bank.label') resolves to landing.rates.options.bank.label
  const { t } = useI18nNamespace('landing')
  return <span>{t('rates.options.bank.label')}</span>
}
```

The unscoped `useI18n().t()` remains available and still takes fully-qualified keys
(`t('landing.hero.title')`) — both styles are supported.

`useI18nNamespace` also returns the namespace subtree as `messages` for components
that prefer direct object access.

## Adding keys

1. Add the key to `messages/en.json`.
2. Add the Spanish translation to `messages/es.json` at the **same path**.
3. Reference it with `t('<namespace>.<key>')` or via `useI18nNamespace('<namespace>')`.

`__tests__/i18n/i18n-dictionary-loading.test.ts` asserts that the English and Spanish
key sets are identical, so a missing translation fails the test suite rather than
silently falling back at runtime.

### Dynamic keys

`lookup` resolves a dotted path at call time, so dynamic keys work as expected:

```tsx
const label = t(`dealStatus.${status}`)
```

Dynamic keys must still exist as literal paths in both dictionaries — the loader
does not resolve template strings.

## Server/client boundary

`app/layout.tsx` only serialises the active dictionary across the server/client
boundary when it is **not** the default locale:

```tsx
const messages = locale === 'en' ? undefined : await getDictionary(locale)
```

For English routes the client already holds `enDict` statically, so the dictionary
is omitted from the RSC (Flight) payload. For Spanish routes the dictionary is still
serialised — it is required for the server-rendered markup and the first client
render to match during hydration.

## Measurement

Capture before/after with the same data, environment and device:

```bash
bun build
```

Then compare, for landing (`/`), `/deals` and `/dashboard` in both locales:

- **Production JS** — DevTools → Network → JS, filtered to the initial document load.
  Look for the chunk containing `messages/es.json`: it must **not** be requested
  for English pages.
- **RSC payload** — DevTools → Network → the `.txt`/Flight request for the route.
  Compare its size before and after for English routes.
- **Chunk sizes** — compare `.next/static/chunks` output between the base commit
  and this branch.

Expected direction of change:

| Artifact | Before | After |
|----------|--------|-------|
| Initial client JS (both locales bundled) | en + es eager | en eager, es in a separate lazy chunk |
| RSC payload (English routes) | full dictionary serialised | dictionary omitted |
| RSC payload (Spanish routes) | full dictionary serialised | unchanged (needed for hydration) |
